# Деплой

Бот использует **long polling**, а не webhook — не нужен домен, SSL-сертификат или
белый статический IP. Это упрощает деплой на любой сервер: от локальной машины до
VPS или облачного кластера.

## Docker (рекомендуемый способ)

```bash
docker compose up -d --build
docker compose logs -f      # логи
docker compose down         # остановить
```

Состояние бота (SQLite) сохраняется в volume `./data/bot.db` — контейнер можно
пересоздавать без потери данных.

## Локальный запуск (для разработки)

```bash
python -m bot.main
```

## Продакшн на VPS / облаке

1. Установите Docker на сервер.
2. Склонируйте репозиторий, заполните `.env` (токен бота, ID администраторов, таймзона).
3. `docker compose up -d --build`.
4. `restart: unless-stopped` в `docker-compose.yml` перезапускает бота автоматически
   при падении или перезагрузке сервера.

Подойдёт любой провайдер с Docker-поддержкой — от небольшого VPS до managed-кластера,
в зависимости от ожидаемой нагрузки.

## Масштабирование

- SQLite подходит для старта и умеренной нагрузки; при росте — миграция на
  Postgres/MySQL через SQLAlchemy делается без переписывания бизнес-логики.
- Рассылки и напоминания уже устойчивы к временным сбоям доставки (ошибки логируются,
  не прерывают процесс).
- Для нескольких инстансов под высокую нагрузку понадобится переход с long polling
  на webhook и вынос FSM-хранилища в Redis — оба решения точечно заменяются в `bot/main.py`.

## Бэкап базы данных

Состояние бота — это один файл `bot.db` (`data/bot.db` в Docker). Регулярное
копирование этого файла в отдельное хранилище — достаточная стратегия бэкапа при
таком объёме данных.
