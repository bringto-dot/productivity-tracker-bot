# Деплой и хостинг

Бот использует **long polling**, а не webhook — значит, ему не нужен домен, SSL-сертификат
или белый статический IP. Это сильно упрощает варианты хостинга при нулевом бюджете.

## 1. Локальный запуск (для демо и скринкастов в портфолио)

Самый простой и бесплатный вариант — держать бота включённым только тогда, когда он
нужен: во время записи демо-видео, скриншотов для портфолио или живой демонстрации
на собеседовании.

```bash
python -m bot.main
```

Пока процесс запущен — бот отвечает в Telegram. Остановили процесс — бот просто не
отвечает, никаких проблем с данными (SQLite-файл никуда не денется).

## 2. Docker (та же логика, но воспроизводимо)

```bash
docker compose up -d --build
docker compose logs -f      # смотреть логи
docker compose down         # остановить
```

Подходит и для локального запуска, и для VPS/сервера, если он появится.

## 3. Бесплатный постоянный хостинг (24/7)

Если понадобится, чтобы бот работал круглосуточно без вашего компьютера, — два
реально бесплатных варианта:

### Oracle Cloud Always Free

У Oracle есть **бессрочно бесплатный** тариф с ARM-инстансом (до 4 OCPU / 24 GB RAM).
Этого с большим запасом хватает для одного Telegram-бота.

1. Зарегистрируйтесь на [oracle.com/cloud/free](https://www.oracle.com/cloud/free/)
   (потребуется банковская карта для верификации личности, но по Always Free тарифу
   списаний не будет).
2. Создайте инстанс с образом Ubuntu (Always Free eligible shape, например `VM.Standard.A1.Flex`).
3. Установите Docker на сервер, склонируйте репозиторий, заполните `.env`,
   выполните `docker compose up -d --build`.
4. Опционально настройте автозапуск контейнера при перезагрузке сервера
   (`restart: unless-stopped` в `docker-compose.yml` уже это обеспечивает после
   старта Docker-демона).

### Fly.io (бесплатный лимит)

У Fly.io есть бесплатная квота, которой хватает на один небольшой процесс без БД-сервера
(наша SQLite живёт прямо в контейнере на persistent volume).

1. Установите `flyctl`, выполните `fly launch` в папке проекта (Fly сам предложит
   использовать существующий `Dockerfile`).
2. Добавьте volume для `/app/data`, чтобы `bot.db` переживал перезапуски:
   `fly volumes create bot_data --size 1`.
3. Задайте секреты вместо `.env`: `fly secrets set BOT_TOKEN=... ADMIN_IDS=...`.
4. `fly deploy`.

## Бэкап базы данных

Всё состояние бота — это один файл `bot.db` (или `data/bot.db` в Docker). Чтобы не
потерять данные — время от времени копируйте этот файл куда-то ещё
(достаточно простого `cp`/`scp`, отдельный backup-сервис не нужен при таком объёме данных).
